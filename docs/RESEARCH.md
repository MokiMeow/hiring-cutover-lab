# Research and design record

Reviewed on 24 November 2026. This tool compares synthetic canonical snapshots. It does not claim a native Greenhouse export or migration integration.

| Primary source                                                                                                                   | Consequence                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Greenhouse Harvest v3 migration instructions](https://harvestdocs.greenhouse.io/docs/step-by-step-migration-instructions)       | Candidates, applications and related resources require deliberate resource mapping. One flat candidate count is insufficient.                                              |
| [Greenhouse cursor pagination](https://harvestdocs.greenhouse.io/docs/pagination)                                                | Any future exporter must follow rel=next until absent and record completeness independently. No exporter is included here.                                                 |
| [Greenhouse active candidate migration](https://support.greenhouse.io/hc/en-us/articles/360040034991-Active-candidate-migration) | A vendor migration has operational scope and constraints beyond a passing synthetic comparison.                                                                            |
| [Datafold data-diff](https://github.com/datafold/data-diff)                                                                      | MIT prior art for database comparisons, archived and oriented to SQL tables. This app needs bounded JSON relation checks and human review, so it does not adopt that code. |
| [OWASP CSV injection](https://owasp.org/www-community/attacks/CSV_Injection)                                                     | Quote every cell and neutralize formula prefixes. Keep JSON as the authoritative machine-readable evidence.                                                                |
| [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)                       | Use Argon2id for new credentials; keep fixed, bounded parameters and random salts.                                                                                         |
| [Node native Argon2](https://nodejs.org/download/release/v24.22.1/docs/api/crypto.html#cryptoargon2syncalgorithm-parameters)     | Use the platform implementation, no invented cryptographic primitive. 64 MiB, three passes, one lane, 16-byte random salt, 32-byte tag.                                    |
| [Bootstrap](https://github.com/twbs/bootstrap)                                                                                   | Reuse MIT CSS, keep its license, restyle locally. No Bootstrap runtime JavaScript or CDN request.                                                                          |

The engine uses indexed IDs and explicit one-to-one mappings. Deterministic validation and comparison own the verdict. A human review is separate. No model, embedding or external AI service participates in a decision.
