# Workspace redesign and independent review

24 November 2026. The redesign uses visual evidence from Tessory's live public read-only MCP catalog. Inspected [Dashboard 1](https://tessory.pages.dev/components/shadcnblocks--dashboard1) and [Dashboard 10](https://tessory.pages.dev/components/shadcnblocks--dashboard10) informed navigation, spacing, panel density and visual hierarchy. The creator's commercial reuse terms were not established, so no creator code or assets were copied. Existing MIT Bootstrap CSS is retained and restyled. The public MCP connection used a temporary client, without editing global MCP configuration or reading private collections.

The workspace now has a compact header and navigation rail, neutral surfaces, blue actions, consistent cards and explicit workflow sections. On small screens the navigation moves above the content and the forms stack. No remote fonts, decorative charts, external image requests or animated effects were added. Wide records scroll inside named, keyboard-focusable table regions.

| Area                     | Implemented change and regression coverage                                                                                                                                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Responsive layout        | Seven widths: 320, 375, 390, 768, 1024, 1440 and 1920 CSS pixels. Also 640 by 450 for a constrained reflow check. Maximum-length labels and usernames are included.                                                                                                  |
| Accessibility            | Labelled inputs/errors, visible keyboard focus, native modal containment, focus restoration, 44-pixel primary controls, meaningful loading and viewer-access states. Axe checks cover login, team, password and evidence surfaces under WCAG A/AA tags through 2.2.  |
| Accurate summaries       | Cards use whole-workspace SQLite totals rather than the latest-500 list. Approved comparisons no longer say they await review. Empty searches and filtered issue lists have accurate messages.                                                                       |
| Import integrity         | HTTP, CLI and browser reject malformed UTF-8 before JSON parsing. Distinct invalid byte sequences cannot silently become equal through replacement characters. Valid Unicode and UTF-8 BOM input remain accepted.                                                    |
| Recovery and idempotency | A lost HTTP response preserves the input and its request key. Retrying the same payload reuses the existing run. Network failures do not mark otherwise valid fields as invalid.                                                                                     |
| Session changes          | API responses and refresh ownership are fenced by sign-in generation. Old responses cannot log out a newer account or suppress its initial data. Expiry closes dialogs, clears displayed records and resets credential fields.                                       |
| Selected evidence        | Detail responses are fenced by selection generation. Review submission captures its immutable target ID and report hash. A delayed earlier detail response cannot redirect an approval to the wrong run.                                                             |
| Team management          | Member creation announces success. Native revocation requires a reason, protects the last administrator and reports failures inside its dialog. Long names use concise visible action text and full accessible names.                                                |
| Authentication and data  | User creation, session creation and password upgrades commit atomically with audit records. A foreign database is rejected before schema changes. Per-account/address throttling preserves eight-attempt protection plus a coarse 60-attempt address cap per minute. |
| Verification evidence    | Primary and supplementary checks record before/after source fingerprints, command/profile identity, actual Node version and output hashes. Stale, missing, skipped, empty, interrupted and unequal-count evidence is rejected.                                       |

Runtime and interface review findings are covered by targeted regression tests. Actual current counts, source fingerprints, browser results, screenshots and incomplete accessibility checks are saved under `artifacts`. Automated checks do not establish every possible device, assistive technology or production environment works. Manual screen-reader certification, real production migration, hosted SSO/MFA and organization acceptance remain separate gates.

Earlier security scans cover earlier source. The receipt must show a fresh matching scan, or explicitly report missing/stale scan evidence. No live ATS access, production writes, deployment or publication was performed in this redesign.
